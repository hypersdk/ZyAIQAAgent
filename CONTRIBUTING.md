# Contributing

Development setup, project conventions, and how to extend the agent.

## Development setup

```bash
cp .env.example .env
make install          # pip install -e ".[dev]" + npm install + Chromium
```

Sanity checks:

```bash
make lint             # ruff (Python) + tsc --noEmit (TypeScript)
argus test exec       # smoke tests against ZYVOR_BASE_URL
argus test run --source local   # full pipeline with the example spec
```

## Repository layout

```
orchestrator/        LangGraph pipeline
  graph.py           node wiring + conditional routing
  state.py           PipelineState (TypedDict) shared by all nodes
  cli.py             Typer CLI (argus …)
  webhook.py         FastAPI GitHub webhook server
  nodes/             thin PipelineState -> PipelineState wrappers, one per stage
agents/              the actual logic, one package per capability
  common/            Pydantic models + LLM factory (shared by everything)
  parser/ generator/ execution/ analyzer/ autofix/ regression/
  api_validation/ logs/ discover/ coverage/ nl_create/ reporter/
github_integration/  PyGithub client, token resolution, discovery download
playwright/          config, fixtures (log/coverage capture), utils, scripts
prompts/             system prompts (markdown) for each LLM agent
templates/           Jinja2: fallback test template + HTML report
tests/manual/        hand-written specs — always executed, never generated over
tests/generated/     generated specs — disposable, regenerated by the pipeline
rust/                zyvor-diff screenshot differ (optional fast path)
kubernetes/ docker/  deployment
docs/                guides and tutorials
```

## Conventions

### Python

- Ruff, line length 100, `target-version = py310` (matches `requires-python = ">=3.10"`); rules are pinned explicitly in `pyproject.toml` rather than left to ruff's own defaults, so a ruff upgrade can't silently widen enforcement. Run `ruff check orchestrator agents github_integration`.
- Every module starts with `from __future__ import annotations`.
- Data crossing node boundaries is a Pydantic model in `agents/common/models.py` — don't pass ad-hoc dicts through `PipelineState` (the `metadata` dict is for counters/bookkeeping only).
- Feature flags are read from `os.environ` at call time (not import time) with an explicit default: `os.environ.get("FLAG", "false").lower() == "true"`.

### The LLM-with-fallback rule

Any stage that calls an LLM **must** have a deterministic fallback and degrade gracefully:

- catch LLM/config/parse errors and fall back (see `parse_spec_content`, `analyze_failures`, `suggest_fixes_from_results`)
- the pipeline must complete with no API key configured
- LLM-generated code must pass the quality gate (`agents/generator/quality.py`) before being written

### TypeScript / Playwright tests

- Import fixtures from `playwright/fixtures/base` (never bare `@playwright/test` — you'd lose log capture).
- `await waitForPageReady(page)` after every navigation.
- Role/text locators (`getByRole`, `getByText`, `getByLabel`) over CSS selectors.
- `toBeVisible()`, not `toBeAttached()`.
- End tests with the console-error check (filter `[error]`, ignore CSP noise).

These aren't style preferences — the quality gate enforces several of them on generated tests, and hand-written tests are the exemplar the generator prompt points to.

## Adding a pipeline stage

1. **Models**: add result types to `agents/common/models.py`; extend `PipelineState` in `orchestrator/state.py`.
2. **Agent**: create `agents/<name>/` with the logic. Keep LLM and non-LLM paths as separate functions with a combining wrapper.
3. **Prompt**: if LLM-backed, add `prompts/<name>.md` and load it via `load_prompt("<name>")`.
4. **Node**: add `orchestrator/nodes/<name>.py` — read state, check the feature flag, call the agent, return updated state. Nodes never raise; they set `state["error"]` or degrade.
5. **Wire**: register node + edges in `orchestrator/graph.py`.
6. **Surface**: extend `PipelineReport`, the report template, and `notify.py` if the results should be user-visible.
7. **Document**: flag in `.env.example` + `docs/configuration.md`; behavior in `docs/architecture.md`.

## Adding an LLM provider

Extend `get_llm()` in `agents/common/llm.py` with the new branch, add the key to `_llm_available()` in `agents/parser/agent.py`, document the env vars in `.env.example` and `docs/configuration.md`.

## Testing your changes

```bash
pytest tests/unit -q                              # unit suite (mypy/bandit/coverage also run in CI — see security.yml)
make lint
argus test run --source local                       # no-LLM path (unset keys first)
argus test run --source local --spec <your-spec>    # with LLM if you have a key
python3 scripts/validate_k8s_manifests.py         # if you touched kubernetes/
cd rust && cargo build --release                  # if you touched rust/
```

Unit-test coverage is currently thin relative to the codebase (~30%, gated at 28% in CI rather than a target) — contributions adding coverage for pure-function modules like `agents/parser/rule_parser.py`, `agents/generator/quality.py`, and `agents/coverage/gap.py` are especially welcome.

## Pull requests

- Branch from `main`; keep PRs focused on one concern.
- Run `make lint` before pushing.
- Don't commit generated artifacts (`tests/generated/*.spec.ts` regenerate; `reports/`, `test-results/`, `screenshots/current|diffs` are outputs). Baselines in `screenshots/baselines/` are the exception when visual tests change intentionally.
- Update docs in the same PR as behavior changes.
